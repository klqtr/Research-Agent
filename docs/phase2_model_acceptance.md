# 真实模型验收清单（尚未执行）

1. 用户提供已授权端点、模型、调用次数/费用预算，并在本地.env填密钥。现状.env缺失、本机11434/1234不可达，没有实际LLM推理。
2. 设MODEL_ENABLED=true与已确认模型；共享账本跨进程累计，不自动删除/清零。费用上限>0时必须给真实输入/输出单价；若为免费本地模型需明确0单价，不能把未知费用当免费。
3. GET /api/model/status仅看配置/账本；POST /api/model/probe inference=false检查GET模型列表。列出模型不等于推理能力。
4. 仅明确允许时，inference=true执行两次小请求，观察JSON和原生工具。拒绝工具请求可能是参数不支持，不能只凭400断言模型没有Function Calling。
5. 开发集先一题，确认模型→search_library/retrieve→结果驱动后续工具→JSON断言→独立关卡→原文跳转。检查raw model_responses、usage、错误、原始引用与版本；不要展示Mock为真实模型。
6. 测试工具参数错误后的修正、无支持断言一次修复、模型超时/预算拒绝/上下文超限、原生工具请求被拒绝时的RAG兼容模式。fallback只是原文摘录，不算真实Agent成功。
7. 真翻译逐段核对术语、公式、引文和专业含义；占位符完整性通过不能替代语言质量。当前没有真实翻译评分。
8. 冻结代码/Prompt/模型/预算与评测集后，在同任务上运行四基线/四消融；生成原始输出后安排真实人工标注。没有数据就保留null，不填写模型准确率或一等奖预测。

默认预算8请求不足以完成96计划组合；需用户明确新的预算，不由研发脚本擅自提高。预算是保守UTF8估算加输出上限，未知tokenizer/供应商计价时不是严格账单保证。无模型时继续离线验收，不无限重试连接。

能力探测特意禁止重试，最多两个实际推理POST；健康GET不算推理。RAG兼容额外综合也计入Agent总回合。账本每次保存原单价，后续改价不重算历史；若既有尝试费用未知，不能把未知当0继续承诺美元剩余预算，需要人工核对授权的预算周期与实际账单，程序不会擅自清历史。
