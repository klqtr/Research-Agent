# 技术方案：研证 ResearchTrace

## 选题比较
官方已限定科研助手，以下是同一必需六模块内的差异化方向，分值为设计判断（1–5），不是实验结果或官方评分。
|方向|创新|深度|价值|可行|展示|综合判断|
|---|---:|---:|---:|---:|---:|---|
|通用多模型论文聊天助手|2|2|3|5|3|易实现但差异弱|
|全自动科研假设与实验代理|5|5|4|1|4|无算力/模型/数据时风险过高|
|版本感知、证据约束的科研助手|4|4|5|4|4|选用，覆盖六模块且可逐层验证|

## 问题与价值
论文修订版本、跨文献数字对比、参考文献生成常导致错引和不可定位的结论。传统关键词搜索无法直接解释证据，通用 LLM 会把记忆混入正文事实。本系统把“论文版本 → 页/段落证据 → 检索 → 结构化主张 → 校验 → 展示”串成可审计工作流。

LLM 适合意图拆解、跨篇综合、双语翻译和写作；数值计算、引文锚点、版本确认与图算法由确定性代码执行。无模型时仅允许明确标记的抽取式检索和算法功能，翻译/综合任务返回模型未配置。

## 核心设计与实验假设
1. 版本感知去重：正文 shingles 相似度与 arXiv 标识结合；相似度仅是词汇近似，不宣称达到学习式语义理解；用户决定保留/替换。对随机改名、版本降级和近题不同论文进行验证。
2. 多文配额检索：BM25 词项与字符 ngram 融合、每篇配额确保跨文问题证据覆盖。对比 BM25、字符检索、融合、无配额消融；不将词汇融合称为 Dense 检索。
3. 证据约束主张：模型必须给出 paper_id/chunk_id/quote；引用必须存在且 quote 是原文子串。该验证证明引用完整性，不证明主张语义蕴含。
4. 版本家族图谱：引用边及 PageRank 核心节点辅助综述；Future Work 仅给“待查证/有后续证据”，不凭相似度断言问题已解决。

## 实现策略
Python 模块化后端、SQLite 元数据/块存储、本地 Web 界面、PDF 原文件预览与页锚点。公开论文来源存档。可选 OpenAI 兼容接口，默认禁用外部推理；超时、有限重试、成本/用量审计。代码执行不接受模型任意脚本，只用预定义绘图与统计工具。

## 评委可核验的差异
证据高亮、跨篇检索轨迹、旧版防覆盖、图谱算法可重算、模型模式明确标识、原始评测逐题记录。创新是应用工程组合假设，不宣称新的基础算法或 SOTA。
